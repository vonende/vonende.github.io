Einführung

Was ist funktionale Programmierung?

Funktionale Programmierung ist eine besondere Art, Computerprogramme zu schreiben. Statt Schritt für Schritt zu sagen, was der Computer tun soll, sagt man einfach was man erreichen möchte – und der Computer kümmert sich um das „Wie“.

Besonderheiten funktionaler Programmierung
  • Keine Veränderungen: Man verändert keine Werte, sondern erstellt neue.
  • Nutzung von Funktionen: Sie geben immer das gleiche Ergebnis, wenn man ihnen die gleichen Werte gibt.
  • Rekursion: Statt Schleifen benutzt man Funktionen, die sich selbst aufrufen.
  • Funktionen können mit Funktionen arbeiten: Man kann Funktionen an andere Funktionen übergeben – wie Werkzeuge, die andere Werkzeuge benutzen.

Diese Art zu programmieren hilft dabei, Programme klarer und einfacher zu testen zu machen. Eine bekannte Sprache, die so funktioniert, heißt Haskell[1]. Diese verwenden wir im Unterricht.

Warum funktionale Programmierung?

Die wesentlichen Vorteile funktionaler Programmierung sind:

Vorteile
  • Klarer und verständlicher Code
    Funktionale Programme bestehen aus kleinen, gut testbaren Funktionen. Das macht den Code leichter zu lesen und zu warten.
  • Keine Seiteneffekte
    Da Funktionen keine globalen Zustände verändern, ist das Verhalten vorhersehbar – ideal für zuverlässige Software.
  • Einfaches Testen
    Reine Funktionen liefern bei gleichen Eingaben immer die gleichen Ausgaben. Das erleichtert automatisierte Tests enorm.
  • Bessere Nebenläufigkeit
    Ohne veränderliche Zustände gibt es weniger Probleme bei paralleler Verarbeitung – z. B. in Multi-Core-Systemen.
  • Wiederverwendbarkeit
    Funktionen sind modular und lassen sich leicht kombinieren oder in anderen Kontexten wiederverwenden.
  • Starke Typisierung
    Sprachen wie Haskell bieten ein mächtiges Typsystem, das viele Fehler schon beim Kompilieren erkennt.

Verwendung des ghci

Im Unterricht verwenden wir ausschließlich die funktionale Programmiersprache Haskell. Wir werden keine eigenständig lauffähigen Programme schreiben, sondern mit dem ghci arbeiten. Der Workflow ist etwa der folgende:

  1. Der Programmcode wird in einem Editor entworfen und in einer Datei gespeichert.
  2. Die Datei wird in den ghci geladen.
  3. Die Code wird im ghci ausgeführt und getestet.

Der ghci wird nicht über ein Menü, sondern durch kurze Befehle gesteuert. Diese beginnen stets mit einem Doppelpunkt. Die wichtigsten Befehle sind:

Befehlsübersicht
Befehl Funktion Beispiel
:load Lädt eine Datei oder ein Modul :load MeinModul.hs
:reload Lädt die aktuelle Datei erneut :reload
:quit Beendet GHCi :quit
:type Zeigt den Typ eines Ausdrucks :type map
:info Zeigt Infos zu Funktionen, Typen, Klassen etc. :info Maybe
:browse Listet Inhalte eines Moduls auf :browse Data.List
:cd Wechselt das Arbeitsverzeichnis :cd src
:! Führt einen Shell-Befehl aus :! dir
:set Setzt Optionen (z. B. Anzeigeformat) :set +t
:? oder :help Zeigt Hilfe zu verfügbaren Befehlen :?
Tip

Einige Befehle lassen sich durch ihren ersten Buchstaben abkürzen. Statt :type kann :t oder statt :load kann :l eingegeben werden.

Lazy evaluation

Lazy Evaluation

In Haskell werden Ausdrücke lazy (faul) ausgewertet:

  • Keine sofortige Auswertung: Wenn ein Ausdruck definiert wird, wird er nicht sofort berechnet. Stattdessen wird eine Beschreibung der Berechnung gespeichert.
  • Auswertung auf Anfrage: Die Berechnung wird erst durchgeführt, wenn das Ergebnis tatsächlich gebraucht wird.
  • Auswertung von links nach rechts: Der Ausdruck wird von links beginnend ausgewertet. Sobald das Ergebnis feststeht, wird die Auswertung beendet. Beispiel: Bei einer logischen Oder-Verknüpfung wird die Auswertung beendet, wenn der linke Ausdruck bereits wahr ist.
  • Effizienzvorteile: Lazy evaluation kann zu effizienterem Code führen, da unnötige Berechnungen vermieden werden. Zum Beispiel können unendliche Datenstrukturen (wie unendliche Listen) definiert und verwendet werden, ohne dass sie vollständig berechnet werden müssen.
